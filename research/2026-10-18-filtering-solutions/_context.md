# 背景（我们的问题）

我们在做一个让 LLM 当半导体晶圆厂调度员的 harness（SMT2020 数据集，约 2,176 个在制 lot、913 台物理机组、每个 lot 几百道工序）。每个决策周期，harness 把工厂状态整理成"决策快照"给模型；模型通过 MCP 工具（read_entities 查询、validate_plan 校验、submit_plan 原子提交）提交计划，或在 single_action 模式下只凭快照一次性输出计划。模型自己选择所有生产任务、机组、组批和队列顺序。harness 还决定"什么时候叫醒模型"（检测到可避免的空闲才开会话）。

决策分三层：物理事实 F（源数据/模拟器）、展示/近似规则 P（harness 设计，用户批准后冻结）、调度决定（只属于模型）。**P 层若隐藏工作，相当于替模型做了调度决定**——上一版（v5）就出过"模型看不到可开工工序导致机器空等"的事故。

Phase R 做了一份现有过滤规则的审计（39 条，含真实数据计数）：
`docs/updates/2026-10-17/project/experiments/harness_v6_20261017/reports/harness_filtering_audit_20261018.md`
务必先通读它（尤其"逐项规则"表、"实测汇总"表、"用户待决定的问题"8 条）。代码在同目录 `src/harness_v6/`；物理模拟器只读依赖在 `/workspace/v6-mac-env/physical/src/smt/`。

用户不是专业排程人员，需要我们把每个待决问题的业界做法和可选方案讲清楚，再由用户决定。

## 硬约束 / 偏好
1. 不能出现"模型既看不到也查不到"的可排程工作；可以压缩、分组、改为按需查询。
2. 优先基于物理事实的规则，少用预测；**增加信息比删除信息风险低**。
3. 不得把调度判断（优先级、选机、组批、排序）挪进 harness。
4. 成本指标：未缓存等效输入 token + 模型请求次数，按模拟小时计；快照有 token 预算，超限会话直接失败（G0 当前状态已经很大，upcoming 一节就 ~3.5k token）。
5. 目标是任意长度仿真（数小时到数十小时），上下文不能随时间增长。
6. 实验要可比：single_action 与 mcp_session 两种模式都要能解释。
