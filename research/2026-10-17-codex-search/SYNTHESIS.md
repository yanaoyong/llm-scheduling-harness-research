## 四份报告的共识

1. **周期滚动 + 异常越级 + 执行层确定性处理** 是文献与工业的主流结构（Vieira/Herrmann/Lin 2003；Ouelhadj & Petrovic 2009；Church & Uzsoy 1992）。“事件驱动”不等于每个事件都重排；“立即处理”也不等于立即调用 LLM。
2. **重排周期 Δ 与计划跨度 H 要分开设，且 H > Δ**。2026 光刻区案例：每小时重排、计划 1.5 小时；Applied：计划 12–24 小时，每 5–10 分钟至 1 小时刷新（厂商资料）。
3. **全局唯一的工序账本**：`未覆盖 = 物理就绪 − 执行中 − 有效分配`，触发、输入、校验、评估共用同一函数；用设备–工序匹配计算可避免空闲，避免一个工序被多台机组重复计数；另设“已分配但长期未开工”指标。
4. **校验分层**：先确定性规范化（`not_before` 作为下界 → `max(now, not_before, 到料, 机器)`；未知到料保持等待条件），再硬约束拒绝；一次返回全部违规；模型修复次数设上限，超过则保留旧计划。
5. **提案 + 同一模型再确认没有独立审核价值**（未找到依据）；可换成 `submit_plan(expected_state_version, idempotency_key, plan)` 原子提交，并保留 `dry_run`。
6. **一次决策运行内允许多轮工具交互**：OpenAI function calling 支持一次响应多个调用；Codex `exec resume <SESSION_ID>` 与 MCP 工具可接入（get_decision_snapshot / query_candidates / validate_plan / submit_plan）。注意：减少进程数 ≠ 减少模型请求数，两者要分开记账。
7. **完整决策状态 + 历史按需加载**：当前计划、执行状态、有效分配、上次回执必须直接可见；稳定资料放提示前缀以便命中提示缓存；工具结果按有效性保留，而不是按时间先后删除。
8. **让 LLM 上移一层**：低频选择策略、生成派工规则或评分函数（FunSearch / EoH / ReEvo / NS4S / CIRP 2026 actor-critic），或周期规划，由确定性程序补齐队列。DynaSchedBench（2026）：多数 LLM Agent 没有稳定超过强派工基线，信息更全、工具更多反而可能更差。这与我们“扩窗无效”的现象相符，但不能说明原因相同。
9. **评估**：三层指标（生产结果 / 计划与执行 / Agent 成本）加稳定性指标（开工时间偏移、改机比例）；共同随机数配对比较；先做 5 个工厂 seed × 3 条模型轨迹的筛查，关键比较再做 20×3；固定 FIFO、CR、规则派工基线；事先登记主要指标；另设决策时延扫描 L = 0/10/30/60/120 秒。

## 对应我们问题的建议起点（均为实验起点，不是验证过的最优值）

| 问题 | 借鉴做法 | 参数起点 |
|---|---|---|
| 1 事件触发过密 | 固定锚点周期 `t0+kΔ`；普通事件累积到下一周期，执行层消费队列；只有故障、紧急批次、Q-time 风险才越级 | Δ ∈ {60,180,300}s；H ∈ {3Δ,6Δ}；普通去抖 10–30s |
| 2 缺口口径 | 唯一的 `uncovered_operations(snapshot)`，加 assignment ledger（候选/有效/执行中/完成/失效） | — |
| 3 过期开工时间 | 确定性规范化，硬约束才拒绝，模型修复上限 | 修复 ≤1–2 次 |
| 4 覆盖太浅 | 按时间覆盖（队列耗尽时刻）检查，瓶颈优先；对比“LLM 定优先级 + 规则补齐” | 瓶颈覆盖 ≥2Δ |
| 5 状态不完整 | 每轮完整决策快照（state_version、计划、执行、分配、等待原因、回执），查询按版本缓存 | 工具结果保留 3–5 组 |
| 6 指标/实验 | 未分配就绪工序时间积分、可避免空闲、稳定性指标、完整调用账本；单因素消融后做 2×2 | 5×3 筛查 → 20×3 |
