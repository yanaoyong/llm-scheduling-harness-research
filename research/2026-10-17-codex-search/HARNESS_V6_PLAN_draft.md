# Harness v6 开发方案（草案，2026-10-17）

## 已确定的方向（用户已同意）
- 实验是先计划后下发的离线模拟（模型思考时模拟时钟暂停），采用周期重排 + 滚动计划，不再"一出现缺口就立即补排"。
- 用原子提交 `submit_plan` 取代"提案 + 确认"两次调用；生产任务仍全部由模型选择，程序不新增、不改派生产任务。
- 模型这一层：本轮继续做 B 方案（模型直接选任务）并改成周期规划；"模型定策略、程序展开"留给已有的 C 方案对照。
- 会话方式：每个排程周期起一个 `codex exec` 会话，会话内通过 MCP 工具多步完成；周期之间不恢复会话，靠完整决策快照衔接；模拟器状态是唯一的权威来源。

## 已知问题（来自 docs/updates/2026-10-17/RESUME.md、最终报告与代码）
1. `environment.py:_gaps` 没扣除已分配给其他机组的工序；`harness/batch_window.py:observe_demands` 扣除了。两处口径不一致，导致重复触发（案例 w1462:131:1、w1942:15:1）。
2. `plan_delta.py:225` 要求显式改写已过去的 `not_before`，不自动规范化（案例 d34-421）。
3. v5 配置 `max_ready_wait_seconds=0`：真实缺口立即触发，周期设计失效。
4. 每次调用只允许一个动作（`contracts.py:181`），并且每次都新起 `codex exec --ephemeral` 进程（`transport.py:424`），整包重发约 20 万 token。
5. 输入只直接展示部分任务（14–15/26），历史结果只保留引用（`capacity_prompt.py:280-344`），导致反复查资料。
6. 评估中"零缺计划"掩盖了物理可加工但未分配的工序（w1703:86:1）；每版改多个变量；每组只有一条轨迹。
7. 源码约 4 万行，多个历史版本并存（`B_delta_gate` v1–v7 等）。

## 开发位置与组织
- 新建精简独立包 `harness_v6/`，只引入 environment、plan_delta、facts、store、部分 evaluation；不带历史版本。原 B 和封存目录不动，复制时记录来源哈希。
- 在新分支开发，每个里程碑一次提交，最后开 PR；在 DECISIONS 里补记原子提交和周期重排两条决定。
- 限制：本仓库没有 SMT2020 数据（`data/smt/SMT2020_LVHM`）、完整保存状态和 tiktoken 依赖。本地只能做单元测试和合成测试，真实轨迹回放需在用户 Mac 上跑，或者把数据拷过来。

## 模块
| 模块 | 职责 |
|---|---|
| ledger.py | 唯一工序账本（候选/已分配/执行中/完成/失效）；提供 `uncovered_ready()`、`avoidable_idle()`（用匹配计算，避免重复计数） |
| normalize.py + 校验器 | 先规范化（`not_before` 作为下界 → `max(now, 到料, 机器可用)`），再做硬约束拒绝；一次返回全部问题；幂等 |
| snapshot.py | 不变的部分放前面（规则/工具/工艺），当前状态放后面（状态版本、计划、执行、账本、等待原因、回执、跨轮笔记）；序列化结果固定 |
| cycle.py | 固定锚点 `t0+kΔ`，计划跨度 H；越级事件只限计划失效、设备故障、紧急批次；周期之间缺口只记录 |
| submit.py | `submit_plan(expected_state_version, idempotency_key, plan, dry_run)` 原子提交，附覆盖报告 |
| mcp_server.py | get_decision_snapshot / query_candidates / read_detail / validate_plan / submit_plan；每次工具调用记录哈希 |
| session.py | 每周期一次 codex exec，接 MCP，不跨周期恢复；本轮预算；解析 --json 分开记账；失败时保留旧计划 |
| metrics.py | 三层指标 + 稳定性 + 每周期调用账本 |
| replay.py | 用封存轨迹的模型决策回放新的触发/账本机制；脚本化假规划器只测机制 |

## 里程碑（全程离线、不调用模型）
- M0 准备：独立包、隔离清单、DECISIONS；复制进来的模块原有测试通过
- M1 账本：w1462、w1942 不再触发；回放统计"已分配却报缺计划"的次数，应对上 10/15/4
- M2 规范化：d34-421 不被拒；硬约束测试结果不变；幂等
- M3 快照：G0 连续读资料的时间点 26/26 任务直接放入输入；超预算按优先级保留；不变部分字节一致
- M4 周期循环 + 原子提交：锚点、越级分类、周期之间零调用；用触发时间算出周期数（粗估 9–11）
- M5 MCP + 会话：用假模型通道离线跑通；记账、预算到了停止、失败保留旧计划、不访问网络
- M6 实验登记：事先写定主要指标、质量底线、seed 方案（5 个工厂 seed × 3 条轨迹）；离线空跑
- 之后申请小规模实际试验：v6 的 B 对比 G0，调用上限事先固定
