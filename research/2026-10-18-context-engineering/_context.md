# 背景（我们的问题）

我们在做一个让 LLM 当半导体晶圆厂调度员的 harness（SMT2020 数据集，约 2,200 个 lot、上千台机组）。每个决策周期，harness 给模型一份"决策快照"，模型通过 MCP 工具（read_entities 查询、validate_plan 校验、submit_plan 原子提交）提交计划；模型自己选择所有生产任务、机组、组批和队列顺序，程序不替模型增删改任务。

现状：真实状态下完整快照约 75.6 万 token（o200k_base）：
- 固定前缀约 56.4 万：规则、工具说明、完整工艺路线表、完整机组静态表（每周期不变）。
- 当前状态约 19 万：约 900 个在加工作业、约 1,000 多道"可开工但未预留"的工序、全部机组状态、待执行任务、hold 等。
上一版预算是 22 万 token，所以第一个周期就超限。

硬约束：
1. 不能为了省空间静默丢弃可排程的工作（上一版出过"模型看不到某些可开工工序导致机器空等"的问题）。可以压缩、分组、改为按需查询，但不能出现模型既看不到也查不到的工作。
2. 主成本指标：未缓存等效输入 token + 模型请求次数，按模拟小时计。
3. 目标是任意长度的仿真（数小时到数十小时），上下文不能随时间增长。
