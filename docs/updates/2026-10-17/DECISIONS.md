# 后续决策与授权边界

下表概括已发生的决定，原话和顺序以 [后续会话](conversations/README.md) 为准。历史授权是归档材料，不自动授权恢复实验。

| 决策 | 落实方式 | 仍须保留的边界 |
|---|---|---|
| 全部生产任务由模型选择 | 查询、提案、独立确认；覆盖和装包只组织资料 | 不用算法补任务或自动应用来压低调用 |
| 原 B 不动 | 独立副本实现、离线检查后再批准有限实际试验 | 不把副本结果写回原 B |
| G1/G2 窗口 272000/544000 | 输入预算 220000/440000 tokens，配套解除固定条数/字符截取 | 本地 tokenizer 不是服务端逐 token 一致性的证明 |
| 大窗口应处理更多需求 | 超预算时分批、缩小所收集范围；保留未展示资料引用 | 不把全部未来工序装下作为实验目标 |
| 一套系统、初次和接续两种策略 | 初次超量需求按完整资料单元分批；接续保留已有任务 | 资料已提供不等于已排程，已提交不等于已开工 |
| 可开工却无计划时立即补排 | 等待上限改为 0；预测提醒合并且不越接续截止 | 预测信息不保证物料已真实就绪 |
| 扩大提前收集范围 | 按输入预算提供相关未来资料，提醒与资料送达分开 | 合成离线容量与实际排程质量分别报告 |
| 增加 G0 对照 | 原版触发/执行，加 G1 同样的窗口和资料组织 | G0 不等同于未经任何包装改变的旧 B 历史运行 |
| 延长同轨迹观察 | 从已封存 882 秒轨迹继续，成功调用不重放 | 三组在 882 秒的计划已因各自选择而不同 |
| G1 第 15、70 次失败各获一次重试 | 保留失败、同模型同状态、未知用量不按零 | 授权不是无限重试许可 |
| G1 第 72 次失败后停止 | 用户选择“不再重试 G1，按三组共同达到的区间比较” | 不补跑到 1800 秒，不删除区间外费用；G2 第 76 次失败也未重试 |
| 本次归档、推送、PR、合并 | 独立归档分支保存后续材料与可核验记录 | 不启动新模型/求解器/仿真，不修改原 B |

同一主会话中保留了从“先讨论”到“离线验证”再到“小规模实际模型对比”的授权推进。归档没有把讨论中的建议当成已实现的机制，也没有把用户验收豁免改成机器严格审计通过。

当前归档请求发生于导出截止点附近，完整发布过程通过 Git 提交、PR 和归档校验记录另行记录。
