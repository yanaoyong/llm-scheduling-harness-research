# G0 / G1 / G2 实际模型对比（2026-10-17）

三组总调用分别为 4、4、4 次。完成目标观察区间的组数为 3/3；三组可直接比较的共同区间为 702–882 秒。

**本次新机制实现了提前补排，但没有比原版规则减少调用；大窗口也没有在这个样本中进一步减少调用。** 三组短区间质量指标相同，但未来已排任务数量不同，不能据此断言长期质量等同。

这是从忙碌工厂保存状态恢复的接续实验，不是初次为 918/2000 台机组排产的实验。原 B 未修改、未打开其运行数据库；新增任务、机组、物料、顺序、开工时刻和显式等待仍全部由模型选择。

## 固定条件

三组使用相同 mixed_702 保存状态、负载及随机数初态，目标区间 702–882 秒；原始工厂终点仍为 3600 秒。模型 gpt-6-astra，medium 推理档位，每组最多 8 次调用，按 G0→G1→G2 交替，无自动重试。查询、提案、确认、修正和失败请求全部计入。

| 组别 | 窗口 / 输入预算 tokens | 执行规则 |
|---|---|---|
| G0 | 272000 / 220000 | 原版即时缺口、周期边界、计划到期或失效 |

| G2 | 544000 / 440000 | 与 G1 相同 |

G0 与 G1 共用资料组织和输入预算，只有执行触发策略不同。G1/G2 提前预算暂为 135 秒（120 秒决策＋15 秒余量）；60 秒用于预测合并，不是可开工需求的等待时间，也不是资料前瞻上限。已提交的有效任务在模拟推进中继续执行。

三组使用上一轮相同的顶层任务说明和封存模型目录。模型仍可以读取额外资料，也可以不接受已校验候选；程序不会自动确认、补选或修复生产任务。

**G0**

- 864→882 秒，启动 2 项，原因 `periodic_replan`（观察结束，不计重排）。

**G1**

- 729→882 秒，启动 8 项，原因 `collection_limit`（观察结束，不计重排）。
- 确认计划累计取消 0 项、替换 0 项；各次确认的显式等待数量为 [0, 0]。

**G2**

- 702→783 秒，启动 5 项，原因 `plan_runway`，预测触发机组 [1232]。
- 783→882 秒，启动 6 项，原因 `collection_limit`（观察结束，不计重排）。
- 确认计划累计取消 0 项、替换 0 项；各次确认的显式等待数量为 [0, 0]。

需要区分同一旧资料反复触发、新预测或更早截止触发，以及真实缺口仍未解决而再次触发。新机制抑制第一类，不承诺屏蔽后两类。收到通知也不代表模型一定会补上全部任务。

具体到机组 1312，G0 与 G1 首轮都没有为它安排任务。G0 等到约 864 秒出现真实缺口才补排，G1 在 729 秒提前 135 秒补排；两组随后都由模型选择 w1463:145:1，在约 864 秒开工，并追加 1728 秒的后续任务。G1 触发包内 9 条候选全部包含，未另查资料。这个例子确认提前补排有效，但调用数仍同为“提案＋确认”，没有因此减少。

G2 的 783 秒提醒来自机组 1232：预计 918 秒需要接续，提前 135 秒正好是 783 秒。其首包已经完整包含 10 条候选，模型首轮仍未安排这台机组；再次提醒后，模型选择 w346:274:1，安排在 918 秒开工。这是为观察终点 882 秒之后准备的任务，调用成本发生在本期，生产收益尚未进入本期指标。

因此，本次没有同一旧资料容量循环，也没有相隔几秒连续重排；每组都是一次中途补排。G1 的第一次执行段只有 27 秒，是接续截止要求导致的提前停止，不是提交后立即循环。G0/G1 的首轮并非完全同一生产选择：机组 1252、1268 分配的两份物料互换，不能把其他后续差异都归因于触发机制。
