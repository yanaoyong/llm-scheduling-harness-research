五、按下列阶段推进

A. 固定目标模型与完成离线工程准备

核实实验入口是否识别目标 GPT-6 Astra 的准确模型 ID、实际上下文/输出限制、reasoning 设置及 Responses/MCP 能力。优先检查当前本地实现与元数据，需要时查官方文档；不凭产品显示名称猜 API 支持。

旧 pin 若不识别目标模型或落入未知模型 fallback，先修复/升级独立构建并重新固定版本和 hash；不得沿用猜测容量，也不得偷偷换模型。非推理的模型列表/认证检查可以先做，首次真实生成必须等离线门禁通过。

按目标模型名和固定二进制重跑完整原生探针，包括工具隔离、禁用工具拒绝、配置/环境继承、超时、usage、压缩检测、大型返回完整性、single_action 空工具和输出 schema。

B. 解决 MCP 容量并完成步骤 4

离线对照完整 512 读取与较小分页方案，必要时实现无损元数据/eligible-set 去重。对照应覆盖：
- G0 与 public:702 / public:1182 / public:1602，explicit 与 dense；
- 固定源序目录分页、显式 IDs、缺失 ID、过期游标、过滤查询、所有实体类型和全部字段；
- 最大实际字段/实体、重复读取、最大登记工具轮数、较大状态；
- 实际 CycleServer 的 read→validate→submit、大 delta、拒绝回执、blocked_queues/absent_operation_tasks；
- 输出/推理预留、累计模型历史、notes/receipt 等后续周期内容，不能只覆盖空初始历史。

离线选择并实现路线，写明为什么另一方案不采用。数据变化时重新生成完整快照、相应 A/B 材料与录制，不复用不匹配的旧 hash。

使用真正固定的原生 Codex、回环模型端点和实际生产工具链录制；只重放 FactReader 产物的诊断不能替代实际 CycleServer 全路径验证。保留每轮完整请求、响应、MCP/JSONL、命令、参数与 hash。

工具轮次至少覆盖正式 max_tool_calls；不能拿“三轮录制”支持模板默认的 100 次工具调用。按双模式、双格式、全部状态及轮次的共同最大值登记 overhead，并核对实际模型窗口 clamp、有效窗口和自动压缩阈值。累计 input+output cap 与单请求 context、单次 reserve 分开。

任何预算失败保持失败、保留证据；不得靠设置一个模型实际不支持的 context 值让纯公式变绿。

受影响检查通过后，运行最终必需离线验收、物理时间窗核验和固定 pin 探针，核对输入完整性。所需集成项目不能靠 skip 当作通过。

C. 真实调用前冻结实验规则

在首次真实 A/B 前，用离线证据冻结 A/B 判定规则、阶段安排、质量指标和阈值选择方法；在 smoke 前确定 Δ 与质量 floor/tolerance。不得利用对应真实结果追改标准。

质量阈值须有可解释的离线参照、单位和方向：throughput 是下限，weighted_tardiness 与 avoidable_idle_integral 是上限，tolerance 是同单位绝对容差。不要设置没有科学意义的宽松值只为通过登记。若短 S0 窗口让某指标无辨识力，如实登记并在报告说明，不事后换终点找显著性。

先做必要的 Δ 离线机制对照，原锚点/事件语义不变。scripted 仅用于机制和量纲校准，不能声称它已验证真实模型质量。
