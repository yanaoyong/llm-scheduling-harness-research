## 范围与修复

1. `build_public_fixture.py`：独立 public_702/public_time_semantics 键；不冒用封存键。
   原测试保留，仅拆开可选证据依赖、消除测试中的二次方 rows() 重算，并增加回归。
2. 过期条件 hold：物理 validator 和来源审计原来仍要求已消失的锚任务；现在到期后
   不再要求该引用，活跃条件 hold 仍拒绝缺失锚。纯函数与真实物理回归均覆盖。
3. 冻结默认 when_ready：观察原来直接索引缺省 not_before 而崩溃；现在只在观察投影
   使用计划创建时刻，不修改提交任务。另固定宿主回执的集合遍历顺序。
4. 独立批次审计不再枚举所有失败组合，仅取每个兼容类的首个最小组合；与小规模
   穷举 oracle 对比，并测试 100 选 25。没有复用 ledger 的匹配辅助函数。
5. 缓存不可变 route 事实，保留原浮点求和顺序；真实观察与原 P 逐字段一致。
   即时账本读取使用拥有输入的只读投影，持久化/可变 API 仍深复制。候选按公开资格
   建倒排索引，避免逐空机扫描整个 WIP；独立审计单独实现索引并对照 100 个多机组
   穷举案例，重复资格不会重复计数。没有预留时机会审计直接返回空见证。它不是最终
   O(变化量) 物理增量实现。factory/store 没有发现需要改代码的物理持久化缺陷。
6. tokenizer 默认从 cl100k_base 改为 o200k_base，与 v5 一致；字符估算器仍仅供离线测试。
7. 每一步先做 ledger↔独立审计及公开资格↔物理 has_legal 对账；完整 ledger 证据
   分段 gzip 保存，内存留同序号/时刻/SHA256。恢复校验物理、账本、周期、积分、步数
   及每周期 token 行。Scripted Submitter 不等于真实 single_action/MCP 线协议验证。

本文“独立审计一致”指不导入 ledger 辅助函数、独立实现**同一贪心策略**。
它能发现实现偏差，不能证明匹配算法最优，也不能发现两者共有的算法近似误差。
此前“穷举匹配一致”仅指给定贪心顺序下的批次选择，不能解释为全局最大匹配。
有效 hold 现在仅计 explicit_wait_idle，不计 avoidable_idle；两指标按机组互斥。
