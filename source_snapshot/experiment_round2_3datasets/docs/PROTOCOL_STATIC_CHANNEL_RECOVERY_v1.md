# 静态直接排程通道恢复协议 v1

这是观察到 `mk08_B_r1` 的 TLS 断连及300秒超时后登记的可靠性补充协议，不是原始正式实验前的预注册规则。原静态/SMT协议、135条核心与45条辅助矩阵、原始失败记录和统计分母保持不变。本文与完成原矩阵后提交的完整资格清单、源码冻结标签共同使用；当前准备工具不等于已经发出恢复请求。

## 资格与一次上限

仅覆盖原静态B的首次请求：恰有一次模型尝试，因明确传输/连接错误超时或失败；原始事件没有完成轮次、最终模型消息、原生工具动作或可接受的完整输出；没有求解、有效排程、语义错误修订或候选选择。凭据、额度、限流问题不归入这条自动恢复路径。资格按原始事件、结果、输入与统一账本独立判断；所有合格格点统一列入，不按实例、质量或其它重复的结果挑选。

原定180条核心及辅助记录全部结束并完成原静态阶段离线回放后，冻结完整待恢复清单及全部180个原结果文件哈希。原证据审计通过只说明失败记录可信，不会把失败变成成功。清单、原冻结文件、原审计摘要、协议和实现须先提交并打标签。原始数据、结果和失败目录均保持原样。原阶段审计正文随清单提交，清单逐项绑定其文件哈希；正文留在离线审计目录，不复制进新的被评测恢复目录。

每个合格逻辑格点最多额外一个新鲜请求。系统/用户提示词与schema必须逐字节等于原失败请求；模型、推理设置、300秒单请求时限、CLI二进制SHA、代理、原生工具权限及解码器保持不变。仅允许grant ID、新隔离目录、call ID等记录身份变化。恢复请求不接收其它方案、其它重复、参考值或研究分析。成功格点不重抽；新回复不合法或再次超时即成为恢复失败，不反馈修订、不再请求，不从多个可行输出中择优。

模型继续决定完整工序顺序和机台。执行器只使用原纯解码器计算时间，并由独立FJSP校验器检查。独立恢复审计另行重建原始事件→final→模型JSON→逐动作解码→完整排程，核对原记录关联、Git/源码/输入、成本账本以及恢复清单的完整性。所有恢复记录放入新的 `runs/recovery_static_*` 目录；跨目录也不能对同一逻辑格点再次创建恢复机会。

## 资源与停止

继续使用同一 `progress/model_ledger.jsonl` 的formal阶段，不新建账本、不重置已消耗/未知用量。共享上限仍为300模型尝试、300万已报告input+output token、4500求解预留秒、14400累计执行墙钟秒；未知用量完成尝试达到3次停止新请求。恢复入口不调用求解器，也不自行授予额度。专用grant由主Agent在清单冻结后按合格格点数量和全局真实剩余额度分配。

原失败与恢复合计最多3次模型调用，累计活动执行时间最多1000秒；这是补充恢复的资源门槛，不重写原试验已失败的墙钟结果。维持300秒单请求时限；若逻辑或全局剩余活动预算不足325秒（含清理余量），即停止，不缩短/提高超时来改变实验处理。有pending账本、未结束原格点、原证据变化、CLI或权限变化、缺失审计、预算不足均禁止新请求。有claim无result的中断恢复不得覆盖或自动重跑。

实际恢复等待间隔、从原首次开始至恢复结束的现实时间跨度、原首次延迟、恢复自身耗时及累计活动成本分别保存。未知token的累计值仍为未知，另可列已知部分；实际费用仍为未知。全部失败尝试保留消耗。

## 报告与交付验收

1. 原首次实验分母仍为Brandimarte27、Hurink81、SMT27，失败目标为null；首次成功率、首次输出率和原质量条件均值不回写。
2. 恢复独立报告合格数、请求数、成功数、失败/停止原因及全部新增成本，不算第四种算法或预先固定的独立重复。
3. 最终静态交付清单逐一列出108个逻辑格点的原成功排程或有界恢复排程，明确来源和两份记录。含恢复的质量表作为单独补充，并标明配对A及恢复身份。
4. 只有全部逻辑格点都有完整可行排程、恢复链通过独立审计、其余SMT与交付条件同时满足，才讨论整体目标验收；不能称原冻结v1首次全成功。恢复仍有缺口时，目标保持未完成。

若需要改变模型、提示词、动作表示、解码、超时或其它被评测方法，则不适用本协议，应新建实验版本并使用受影响数据的预留验收集。修改排程质量目标或用低质量结果触发重抽均不允许。
