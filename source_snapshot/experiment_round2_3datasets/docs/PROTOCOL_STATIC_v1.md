# 第二轮静态正式协议 v1（2026-10-09，冻结后不可原地修改）

## 问题、数据与参考值

标准非抢占 FJSP，所有作业在 0 可用。每道工序恰选一台合格机器，采用机器相关正整数工时，遵守工艺链与单机容量，最小化 makespan。不加入维护、换型或额外优先级。输入来自锁定的 SchedulingLab 源，逐工序与 ScheduleOpt JSON/文本交叉检查；版本、许可、哈希及差异见 data/fjsp 与 docs/fjsp-source-audit.md。模型仅接收合格机器、工时、工艺结构；不接收实例名称、参考值、检索链接或其他运行的结果。

开发：Brandimarte mk01/mk02，另先验增加 mk10 做240工序规模验证；Hurink la01/ft06 的全部 e/r/v。正式：Brandimarte mk03/mk05/mk08；Hurink la02/la06/la11 各 edata/rdata/vdata。预留：mk04/mk06/mk09、la03/la07/la12 全部 e/r/v。Hurink 按基础实例整组划分。3个Brandimarte ×3臂×3重复=27；3个Hurink基础×3变体×3臂×3重复=81。核心共108条；固定组合F另36条，不计核心。

选择依据：Brandimarte 覆盖不同规模及结构，Hurink 覆盖10/15/20作业规模；在任何正式运行之前锁定，不按成功率选择。参考表全部在离线评价器中。维护表报告上下界相等标 reported_optimal_unverified；BKS、下界、独立验证最优分别命名。模型自己的本次求解界可以反馈给 C，它不是外泄的参考答案。Hurink 变体不是嵌套资格集合，差异解释为具体柔性结构变化，不作单因素因果推断。

## 方法及隔离

A：OR-Tools 9.15.6755，可选区间 CP-SAT；约束实现见 src/fjsp/solver.py，来源说明 docs/classical-model.md。单线程、每次最多30秒求解预算，种子11/22/33。固定参数按开发结果确定：Brandimarte PORTFOLIO_SEARCH，Hurink AUTOMATIC_SEARCH；randomize_search=false。开发中自动/portfolio分别在 mk01,mk02,mk10 上得到40/26/262与40/27/249，在la01三变体得到609/570/571与609/573/572；因此不故意维持在该类开发集上更弱的参数。上述仅用于调参，非正式结果。

B：真实 gpt-6-astra / medium，完整决定全局工序顺序及机台分配。紧凑输入 jobs[j][k]=所有[machine,duration]选项；输出 N 个[job,machine]动作，某作业每次出现表示该作业下一道工序。解码器只按模型选定顺序计算 start=max(job_ready,machine_ready)，不排序、不插空、不选机、不补缺失动作。此表示不提供任意主动等待，所产为该顺序下的最早开始排程；限制如实报告。完整输出经过独立检查；错误最多有限反馈修订。首次完整可行即结束，无模型外代排或自动接管。

C：同模型、推理配置及信息内容；选择 solve 的模式（AUTOMATIC/FIXED/PORTFOLIO）、随机化、种子、时限，获得本条运行的界、状态和独立检查，再决定再次求解或显式 finish(candidate_index)。与A共享约束模型，最多2次solve、累计30秒；最多3个模型响应，需预留最后一次finish。无显式选择即失败，不由工具偷偷选最优候选。

F：预定辅助固定组合，同总30秒：AUTOMATIC/FIXED/PORTFOLIO各10秒，seed分别为重复种子、+1、+2，单线程、非随机化；取独立可行候选中makespan最小者，平局取最早候选。F不调用模型，独立统计。它检验固定组合能否解释C的改善，不能证明覆盖所有可能固定策略。

所有调用使用全新、无原生工具、ephemeral隔离CLI上下文。每条实例/方案/重复有独立目录及候选；提示词只来自白名单观测与本条反馈。开发协作Agent不充当被评测模型。实际原生工具事件非零的模型请求不得成功。

## 资源、失败与成本

开发探测：小B约98秒；240工序显式id版240秒超时；紧凑版约149秒成功。正式每调用硬超时300秒，B/C每条最多3调用，每条决策循环墙钟上限1000秒，返回超时不接受为成功；进程终止回收可能额外数秒。CP-SAT每次内部预算≤30秒，记录实际求解及含建模墙钟；A与C同累计预算，模型开销计入端到端。

全轮开发最多24次模型尝试，正式全三数据及辅助共享最多300次；SMT的配额在其正式协议单列，不能复制总预算。正式共享已报告input+output token停止阈值3,000,000，开发400,000；缓存输入是input子集。CLI无法施加可靠的服务端硬输出token上限，故在后续请求准入时检查已报告用量，可能超出最后一次有界调用的量。未知token不当0；同阶段未知用量完成尝试达3次即停止新模型请求。输入提示最多120,000字符。账本 reserve/finish 带锁，失败也消费尝试；无自动网络重试循环，不购买额度、不使用额度重置。

全正式核心与辅助累计已完成运行墙钟上限14400秒，批次在下一格点准入前检查，可能超出最后一条已准入的有界运行。正式solver累计预留上限4500秒：静态A/C最多2160秒，F1080秒，其余供SMT各臂与固定辅助；不自动扩限。真实货币费用、服务端纯推理耗时及不可观察HTTP重试数均null。开发协作会话费用不可得，与被评测调用分开。CLI调用阶段包含启动/网络；端到端从运行器开始加载输入，到求解/模型/独立检查、结果构造完成，不含最终result落盘。首个有效输出时间单列；A/C内部首witness不是已独立验证时间。

失败分为环境依赖、通道、解析/语义、动作错误、预算/超时、不可行、记录不一致、可行质量差。失败目标null，不从分母剔除；质量均值条件于成功。C首次输出指标解释为首次模型动作产生的首个求解候选有效，另报告首次动作合法与最终显式提交成功；与B完整排程输出层次不同。

## 冻结、执行与验收

每批执行文件/配置/依赖/协议/参考表先提交，冻结清单记录code_commit、数据/文件哈希、精确矩阵、有效配置各repeat哈希、tag。冻结清单自身另存且不做自引用hash。每条运行保存freeze副本及其hash、完整源码快照、配置/输入/结果、原始模型事件、工具参数、求解轨迹、用量与失败。正式默认串行，单worker；不同时开展其他本实验CPU密集求解/仿真。桌面背景活动不能完全隔离，报告不称专用基准硬件。

恢复只复用身份、哈希相符且已完成的记录。started无result标为不完整，不猜测进程死活，不自动重跑；必须保留失败/中断证据并按新版本恢复协议处理。查看正式结果后不得调参再声称同组未见；需新版本及预留集。无需超过A，但最终验收版本所有静态格点均须提交完整可行排程。

离线回放：独立重算完整性/资格/工时/顺序/容量/makespan；核对原始JSON事件→final→模型output→动作→最终排程，成本账本、Git/tag/snapshot/config/data；按冻结矩阵列出成功、失败、不完整、未开始。报告引用回放结果与冻结参考表，给每实例每臂质量/稳定性/相对各类参考及配对A差距、用量、延迟、修订率。新鲜模型运行仅保证流程可复现，不保证随机输出完全一致。
