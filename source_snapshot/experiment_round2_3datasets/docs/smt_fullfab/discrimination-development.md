## 指标和比较范围

主指标 (J=\sum_i w_i\max(0,\min(T,C_i)-\max(t_0,r_i,d_i))\)，单位为加权 lot·秒；未完成 lot 的 (C_i\) 在观察窗末截断。默认开发权重为 priority 10/20/30 → 1/2/3，尚待正式预注册冻结。窗口开始前已经逾期的 lot 从窗口起点计入，不重复收取历史逾期。不能只统计完成 lot。完整定义见 [metrics.md](metrics.md)。

下列 reference 都显式考虑 913 台生产设备，虚拟 Delay 不承担生产。CR 与 FIFO 使用相同的高优先级、少换型优先层级，然后分别按 critical ratio 或当前工序 ready_since 排序，随后按交期、lot ID 等固定规则打破平局；同 part/工序按最小与最大批量约束需求组批。这两个名称并不表示不带优先级的纯 CR/纯 FIFO，也不是官方 AutoSched 的校准复现。它们是参考策略，不是 A/B/C 的 fallback。

四份参考运行的输入数据哈希相同。8 小时 CR/FIFO 的完整初始 manifest 也相同，包含 seed、913 台设备、初始 lot、路线、日历和输入哈希。其 reference.py、metrics.py 与旧物理内核文件哈希相同，但新 environment.py、runner.py、audit.py 等源码哈希不同；因此下述差值是开发记录的描述性分离，尚未排除版本变化的混杂，不能作为纯策略因果效应。

## 已观察到的差异与吞吐折衷

8 小时 CR 的 J 比 FIFO 低 7,047.96 加权 lot·秒，按 FIFO 为分母约低 2.2048%；与此同时只完成 10 lot，FIFO 完成 12 lot。CR 的终点逾期 WIP 为 9，FIFO 为 13；CR 的终点总 WIP 反而多 2。应同时报告这些值，不能把较小 J 解释为所有生产指标都更好。

| 8 小时分项 | CR | FIFO |
|---|---:|---:|
| 完成 lot 对 J 的贡献 | 79,832.72 | 16,469.68 |
| 未完成 lot 对 J 的贡献 | 232,782.00 | 303,193.00 |
| 换型损失代理秒 | 386,077.03 | 370,375.29 |
| batch_fill_mean | 0.930159 | 0.933173 |

仅按完成 lot 的逾期项，CR 看起来更差；计入未完成 WIP 后，总 J 的次序相反。这正说明不能用“没完成所以没逾期”的指标奖励拖延。换型损失是已保存的代理统计，batch_fill_mean 是批派工填充率均值，均不能替代主指标或吞吐。上述方向只描述这两份保存结果，不推广到其他种子、负荷或长期窗口。

全厂的可选空间也已经不同于旧两机试验。8 小时 CR 的保存机会审计检查了 6,642 次实际生产派工，其中 3,632 次有多种当下合法机台/组批选择，3,051 次存在加工时间差异，307 次存在换型时间差异，644 次至少存在一个非零换型选项；单次最大合法机台/组批组合数为 1,420。FIFO 对应实际派工检查 6,533 次、多选 3,556 次。24 小时 CR 对应 20,262 次派工检查、多选 12,013 次。这些是轨迹内重复观察，彼此相关，既不是独立统计样本，也不是模型决策轮数。合法需求被显式计划或等待覆盖，不等于所有 lot 已获服务；未排队列、等待和终点 WIP 仍须保留。

## 尚缺的验收证据

现有一条 8 小时 CR 与一条 FIFO 记录显示指标并非恒等，且包含吞吐折衷；但尚不能确定这一差异稳定、显著或达到业务可感知幅度。1/8/24 小时同种子的嵌套窗口、一个轨迹里的数千派工、开发修复版本以及同种子重复执行，都不能冒充多个独立场景种子。

后续正式设计需先冻结同一环境、指标权重、参考规则、共同 A/C 算法和成本口径，再在独立场景种子上做配对参考比较，并按预注册方案处理模型内部重复。由种子层面的配对差值估计方差，指定显著性水平、功效和具有业务意义的效应阈值，才可计算或模拟 MDE 与所需样本量。目前没有可报告的方差、置信区间、p 值、功效或数值 MDE。失败率和预算耗尽也要作为结果保留，不能只挑选完成窗口。

因此，本摘要提供开发场景“存在可区分的保存结果与真实选择空间”的证据；同版本因果比较、统计辨别能力、完整 A/B/C 成本对照、官方行为校准及正式验收仍未完成。
