## 新接入版本应固定的边界

1. 原 package 的完整物理状态、原前史、原 manifest SHA 与精确依赖是共同输入。新分支登记应绑定 `shared_start_id`、原 manifest SHA、arm、run_id、注册 SHA、T0/T1/H 与观察/计划参数；外生场景保持原事件身份随机机制。
2. 保持 `0<T0<T1=H`。观察长度是 `T1-T0`，不能把绝对终点 H 混称为新增试验时长。原阶段授权的 1/8/24 小时长度与新绝对 H 的账本表达，需要在新登记契约中明确区分，不能让宿主猜测或规避范围验证。
3. 当前 package 支持自然过期计划、真实在加工任务和未来队列，不支持非空跨界冻结承诺。新接入不得自动排空在加工任务、删队列或强行清计划来满足边界。遇到不支持的冻结承诺应保留失败；后续扩大支持需单独实现和验证。
4. 恢复后第一次公共问题在三个分支逐字节一致；原物理状态在第一次明确提交前保持一致。禁止宿主提前调用推进、触发虚拟派工、替 B 选任务或给 C 自动提交工具结果。
5. T0 首次新计划与后续事件重排由对应方案明确负责。A 的首次 CP 及后续周期在新分支资源中登记；C 仍由模型选工具/参数、查看候选、明确提交；B 仍由模型决定具体排程。参考预热历史不作为任一被测方案的决策成功数。
6. 新周期以共同 T0 为锚，事件重排不推迟下一周期。T0=61 秒这类非整周期边界必须纳入验证，否则与零点对齐的错误会被整周期起点掩盖。物理时间与 `observation_start` 原值均不修改。
7. 所有原前史继续进入完整物理/来源核验；新的控制器归属审计从唯一已验证的 `snapshot_loaded` 之后开始，并绑定原预热计划和 `executed_tasks`。继承在加工任务在 T0 后完成仍是共同物理过程，不是新模型派工。任何新的生产派工必须归属本分支的明确计划。
8. 原始账本保存共享生成一次、各分支恢复和运行各自成本。对照分析明确报告共享成本及分摊口径，不把共享成本消失，也不把同一原调用重复记为三次；失败和未知用量继续保留。
9. 指标计算完整保留原投入和 WIP，只把积分/计数窗口显式限定为 `[T0,T1]`。需验证起点已逾期 WIP、跨界在加工、完成者周期、窗口内投料及终末积压；不能只比较六项汇总指标。
10. 保存原快照、完整 trace、首问题、所有明确计划、模型/工具原输出、周期收据、分支完整快照和独立审计。新验收应同时证明终末 H、分支期间指标与动作归属，不能只复用冷启动 `accepted` 标志。

## 下一轮最小实现与验收顺序

先执行已封存的 shared_start/prefix/worker/host 首次串行测试，再执行原 seed 1701、T0=61、T1=H=121 的恢复工程探测。若失败，按原边界保存失败并修复问题；不能为寻找容易通过的状态而移动 T0 或清空设备。

恢复工程探测通过后，在新的版本文件中实现上述接入，保留旧冷启动入口。首先验证共同输入和分支审计，再分别连接真实 A、B、C 决策循环。新增实际控制器探测前须冻结可审阅的参数、完整成本与资源上限；已有调用次数/token 豁免继续适用，不重新询问该额度。

必要的接入测试包括：非整周期 T0 的边界对齐；首次明确提交前状态不变；旧计划/已派任务原锚替换拒绝；未知提交结果禁止重放；缺失、重复、偏移或伪造恢复标记拒绝；前史派工与新分支派工归属区分；继承加工完成不冒充新派工；真实模型原调用身份及全部求解成本闭合；完整指标窗口与原 H 区分。微型测试不能替代真实分支运行。

该工程探测的参考重放、随后真实控制器共同起点验证、基于稳定性诊断的预热设计是三个不同阶段。当前均不能据此宣称稳态、官方数值复现、7/14/28 天能力或正式 A/B/C 排名已完成。
