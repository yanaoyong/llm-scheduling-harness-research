# 全厂环境、观察与恢复独立审查

审查日期：2026-10-09。范围是 `environment.py`、`runner.py`、它们继承的 adapter-v2 物理行为，以及 `observation.py`。未执行优化、模型或长周期仿真。验证使用真实官方源的轻量构造、明确的单次派工、故障/PM临界值人工注入，以及在加工快照恢复后 1 秒推进；人工注入仅为测试，不混入官方实验结果。

本次可确认：913 台生产设备都有控制责任；未提交计划时出现合法生产需求会返回 `uncovered_demand`；新 `_outside` 仅执行虚拟等待；已发生生产事件可绑定明确计划任务。完整快照能保留在加工任务及其私有事件信息，并在本次短期 roundtrip 测试中产生相同后续物理状态。**这些证据不等于全厂正式验收、稳态校准或无漏派证明。**

## 已发现并修复的问题

|优先级|问题|修复与验证|
|---|---|---|
|P1|从 checkpoint 恢复后 runner 的新计划版本从 `0` 开始，与恢复的 `plan_versions` 冲突，第一次重提就失败。|主实现已改成 `run_id:count`。恢复状态保留已执行任务与既有版本，测试证明重复旧版本仍被拒绝。完整恢复 runner 的资源续记仍需下一阶段验证。|
|P1|`commit_plan` 接受有效期以后的 not_before；任何 pending task 都让 `_gaps` 跳过该机，可将非法远期任务伪装成当前有覆盖。|主实现增加 `not_before < valid_until`；专项负向测试通过。合法未来任务仍表达该方案的等待意图，需独立统计其造成的闲置与未服务需求。|
|P1|原 problem 导出使用 `job.lot_end`、`process_end`、`machine.ready`，泄露未来已抽样运输/加工/未触发计数 PM 的实际结束时刻。|新增独立 `observation.build_problem`：只输出当前 busy/down 布尔值；可用时间、剩余加工、运输使用源均值、已观察起点/setup、已经发生的停机时间。未来随机状态、队列、seed 不进入 problem。修改私有未来加工、运输、machine ready、queued events、当前停机未来长度及计数 PM 抽样，观察结果保持不变。|
|P1/P2|未来的 SVESTN/FORSTEP 绑定只在环境实际派工后形成，旧 exporter 丢失计划内两工步须用同机的关系。|新观察对展开内的绑定源/目标给 `same_machine_as`；既有绑定限制设备资格；历史或展开外未知绑定显式标 `qualification_uncertain`。测试使用真实源 w81 对应的绑定链验证。|
|P2|冻结未开工任务在 earliest start 已过去后，既要完全保留又要求 not_before≥当前时刻，合法保留被拒绝。|主实现允许精确保留的冻结任务带过去 earliest start；延误冻结任务保留测试通过。完整优化器如何保持原任务 ID/精确字段仍不是本次微测试的验收范围。|

新观察接口采用 `smt-fullfab-problem-2`，不与旧导出内容混称同一冻结版本。名义预测会受采样、返工、实际加工时长及故障影响，必须由共同执行器根据已观测状态重校验；不保证名义计划始终可执行。

## 新观察的具体口径

- 在加工 job 的预测完工时间来自公开源加工均值、已开始的 setup、过去已经发生的停机和当前修复的均值残余，不读取未发生的真实完工时刻。若均值已耗尽而任务仍忙，使用 1 秒的名义下界并标示该局限，不能把它理解为真实剩余 1 秒。
- 运输已经开始时，实际加工完成时刻属于过去观测，可以用于“过去完成时刻 + 期望运输”；未来真实运输结束时刻仍是私有状态。
- 当前故障/维护的未来 duration 不进入观察；多次重叠维修只使用最后已观察维修的均值残余近似。该近似需要误差诊断，不能宣称精确 availability。
- 计数 PM 是否被片数阈值触发可知，但尚未发生的 PM 时长使用源分布均值。
- 虚拟等待作为名义工步之间的时间滞后，包含其处理/装卸/后续运输均值；这些虚拟步骤的抽检/返工百分比和条件性保留在观察中，不作为生产决策设备。
- 预测未来步骤默认“不跳步、不返工”的条件路径。目标 step/visit 若因观测结果改变，必须触发修订，不能修改过去轨迹。
- 全部历史中观察到的 dispatch/downtime 被增量索引，避免每次重新解析完整 trace。索引不修改环境；跨 snapshot 后从完整历史重建。
- 公开投料流与已知维护窗口尚未加入 nominal 展开，当前接口依靠新观察事件触发重排。这是可改进项，不能宣称已使用完整可用预告信息。

## 尚未关闭的风险

后续复核（同日）：下列初审第1项已增加环境/观察/旧物理/vendor代码逐项指纹；第2项已增加seed/horizon校验与累计资源checkpoint，第3条失败A的冻结源码实际恢复获得完全相同状态哈希（含841个在加工任务），证据见 `artifacts/smt_fullfab_recovery/A_v3_state_restore.json`。这仍不是追加排程后的完整恢复验收。第4项已实现独立逐时间推进机会回放，实际检出A v2的未来失效任务遮挡缺陷；环境0.2已修复为提前扫描所有pending任务，仍需修复后的完整运行通过。以下原始风险条目保留发现时语境，不能当作这些后续修复未发生。

1. **快照代码依赖。** 当前 checkpoint 校验状态哈希、数据哈希、固定旧物理模块哈希和固定版本字符串，但未完全绑定新环境、观察导出、vendor 数据类和依赖版本。每次运行的 source_snapshot 有这些部分来源记录，但 `from_snapshot` 未逐项强制校验。正式运行前应增加完整执行依赖指纹并做篡改负向测试。
2. **恢复成本与场景身份。** runner 的新的局部计数/求解账本从恢复 run 开始；必须明确与前序 checkpoint 的账本关联，不能把恢复前消耗变成零。配置 seed 与 snapshot 内真实 seed 若不一致也应拒绝或明确继承。正式恢复需验证累计预算、重复调用规避和统计窗口定义。
3. **冻结计划整合。** 新观察携带 frozen_tasks、operation_ids；已经错过的 earliest start 对优化器的名义 start 下界设当前时刻。执行器仍要求保留原任务字段。优化器输出重命名和重排的处理需完整集成测试；本次只验证环境原任务的不可删除和合法保留。
4. **无漏派证明尚缺。** `_gaps` 检查即时未覆盖机台，计划源审计证明实际派工来自计划。但它不独立枚举每个事件时点的全部合法需求，更不能仅凭 scope=913 或 success 证明不存在长期排除。已有审计字段 `absence_of_unreported_legal_demand_certified=false` 必须保留，正式验收前需独立机会回放。
5. **长时域规模。** 旧物理层保留所有历史 jobs 和全部 trace，故障处理会扫描历史 jobs；snapshot 复制完整 trace。新观察将原“每个在加工 lot 扫一次全部 jobs”降成全 jobs 单次索引，但历史仍持续增长。runner 的 256 MiB trace 上限以及按计划边界检查的 wall 上限可能在长窗触发，不能从 1 小时成功外推 7/14/28 天可运行。
6. **源语义局限。** CQT 没有完整硬约束/监控、初始 1311 lot 缺历史 binding、433 lot 缺 CQT 起点、wafer cascading 不是逐 wafer 内核；详见 `semantics-20261009.md`。完整快照只能忠实保存所选环境产生的状态，不能补出不存在的生产历史。
