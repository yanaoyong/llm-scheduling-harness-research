# 全厂排程问题规范：开发版

本规范描述当前修订仿真内核上的问题，不宣称等价复现 AutoSched。源文件、初始化与约束边界见语义/校准报告；任何正式版本需固定具体文件哈希。

## 状态与决策

研究实体为 lot（25 片）、条件工艺路径及 visit、913 台生产机器、兼容批和共同物理事件。10 条产品路线、105 个生产设备族、2156 原始 WIP、21 条周期释放流。时刻零额外释放的 lot 单独计入窗口投入，不能把所有窗口都当作“新增31 lot”。机器任务执行完成和 lot 全路线完成是两个不同概念。

每版计划必须声明完整生产 scope，给出准确 lot/step/visit、机器、批成员、机器内顺序、开始下界及有效期。未来条件路径可被实际跳步/返工改变；所有 pending 任务一旦被已观测路径淘汰，执行器立即报告失效并请求本方案修订。执行器不自动删除、替换、选择唯一合法生产动作或补全遗漏。

已经开始的加工按共同物理规则推进。计划冻结要求未开工冻结任务原样保留，不能改写历史；当前开发优化运行 freeze=now，非零冻结区间仍需完整优化集成验证。等待必须显式声明机台、截至时刻和理由，或者跟在准确计划任务后。统计未入计划的工序、最长未计划等待、窗末 WIP 和吞吐，防止把全机等待称作优质覆盖。

## 观察与随机性

运行时只接收白名单 `problem`、本方案已有选择和工具反馈。未来已抽样加工/运输/维修时间、未来故障与返工结果、参考答案、其他方案结果及研究协作上下文均不提供。紧凑分页包含每个展开工序，采用稳定源顺序，无优质候选筛选。

加工和可用时间预测来自公开源均值与过去观测。已超均值但仍加工的任务使用明确标注的名义残余近似。已知维护、公开投料预告尚未完整进入 nominal 展开；新观察事件触发补排。因此相同可观察权限不等于实现已充分利用全部公开信息。

外生抽样按 seed 与事件身份进行 SHA256 绑定；策略改变批成员时，相应加工事件身份也可能不同，不把“同种子”当作逐事件完全相同的结果。完整私有快照保存队列、加工、setup、绑定、日历、PM、投料、事件堆、计划及完整历史，并绑定数据和实现哈希。模型永不读取私有快照。

## 质量、合法性和成本

主候选指标为完成与未完成 lot 共同贡献的优先级加权累计逾期时长，数学定义及分母见 [metrics.md](metrics.md)。权重 10/20/30→1/2/3 属于开发提案。质量、全窗成功率、可行性与资源成本分开报告；失败记录不删除、不补成成功。计划覆盖范围为913并不能单独证明无漏派或无饥饿。

独立检查依次重建计划来源、物理合法性、每次时间推进前的合法需求与时间边界。B/C 另核对原始提示词、模型输出、真实 token/时间、隔离事件、工具参数、候选/提交关联与预算发生顺序。检查器不相信 `result.status` 自报成功。

当前目标是仿真暂停期间的决策质量。模型墙钟未随意加到仿真末尾，也未模拟真实生产在思考期间的处理；因此不能声称线上收益。未来在线设计需预先定义旧计划继续、空闲、过期、反馈及计划修订的一致处理。
