# B V8：固定身份与草稿发现接口修订

本版本是开发阶段的显式协议变更，不将 V7 或 recovery_001 的失败改成成功。模型仍是 gpt-6-astra / medium，单次最多 600 秒；用户已豁免累计调用次数和 token 额度。所有调用、失败、未知用量及费用未知状态继续留在同一追加式账本。

## 变更原因与范围

recovery_001 新增 55 次真实请求，已知输入输出合计 1,309,537 token。最后一次虽然传输成功，但模型把固定 source_sha256 从 64 字符抄成 62 字符，严格绑定层在执行前拒绝。此前已封存的第二版草稿因保留/取消集合不一致未通过编译。

V8 只改善中性接口：动态 JSON schema 对已确定的身份、上下文和草稿引用使用单值枚举；每轮直接列出全部现存草稿元数据，避免丢失哈希后无法发现。模型仍自行决定新草稿、具体任务、设备、组批、排序、等待、取消和替换，并在检查候选后另次明确提交。没有默认任务、默认候选、优化器补排、自动修复或静默接管。

## 恢复与归属

从原 V7 的完整物理检查点恢复：t=803.2499999999999，绝对终点 3600 秒，周期锚点 0，下一边界 1800。根核验已确认失败恢复段除真实 snapshot_loaded 标记外没有改变完整物理状态。使用原检查点与完整原事件前缀，新运行增加一个真实恢复标记。原物理源码锚与新版协议源码清单分开冻结。

新建空 memory、空草稿、空候选的 Interaction。旧未提交草稿完整留档，但不导入新交互；旧第 186 次输出永不补执行。新的唯一模型索引从 187 开始，使用新调用 ID 与新目录。首个新明确计划提交前禁止物理推进。所有 913 台生产设备仍受 B 控制。

## 成本与资源

祖先累计 187 次请求、4,475,910 已知 token、1 次已完成但用量未知；另有单独通道探测 1 次、5,110 已知 token。全部美元费用未知。全局其他旧失败/未知/未结项不删除。开发协作成本单列未知。

继续扣减原 21,600 秒宿主运行资源和 16 GiB 保留文件上限：根核验已计 17,215.7923935429 秒和 2,231,144,880 字节；新版保守最多使用剩余 4,384.20 秒和 14,948,724,304 字节，包含恢复、模型、推进与审计，最终以真实外层退出和外部计时核验。不重置祖先费用。离线实现和测试独立记录。

## 验证与停止

冻结前执行纯协议、准入及一次有限合成链路测试，测试不冒充真实模型或工厂表现。真实运行失败时不自动重试，保留原模型文件、账本、检查点、错误及真实退出记录。完成 3600 秒后仍须全调用归属审计、完整物理轨迹检查、源文件围栏、最终账本与外层资源闭合，才能记为此开发续作通过。完整研究和正式实验尚未完成。
