# 第二轮实验：方法、来源与解释边界

本轮研究比较经典优化方案A、直接排程Agent B和求解器增强Agent C，分别考察静态排程质量、设备柔性结构变化和动态半导体场景适应性。本附录说明已冻结的方法及开发验证；正式运行结果、成本和最终验收见[中文报告](REPORT_zh.md)。文件名保留开发时路径以兼容已有引用。

Brandimarte用于校准静态排程质量，正式预选mk03、mk05、mk08；Hurink用于比较同一基础实例的edata/rdata/vdata，正式预选la02、la06、la11，按基础实例整组划分开发、正式和预留集。两者均为标准FJSP：工序选择一台合格机器，按对应工时连续加工，满足工艺链和机器单容量，最小化最大完工时间（makespan），不额外加入维护或换型。SMT2020使用完整官方Dataset 2 LV/HM动态工厂环境，正式预选外生种子801/802/803。每个实例或场景中A/B/C各重复3次，计划核心记录分别27、81、27条，共135条；预定固定参数辅助对照另45条，不冒充第四种主要方案。[静态协议](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/docs/PROTOCOL_STATIC_v1.md)、[动态协议](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/docs/PROTOCOL_SMT_v1.md)保存完整矩阵和预算。

静态输入锁定SchedulingLab的`ac4c340…`提交，并与ScheduleOpt的`f89e5b0…`文本、JSON逐工序核对；139个源文件有内容哈希，33个开发、正式及预留实例的选机、工时和前后序均已交叉检查。仓库声明的许可证分别为MIT和CC-BY-SA-4.0。Hurink原论文已取得并核对约束与实例构造；Brandimarte原论文仅核实书目信息，全文表格与原始文件字节未独立复核。双源一致也不等于两个数据库没有共同上游。[来源审计](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/docs/fjsp-source-audit.md)保留完整版本、论文链接、命名和机器数差异。

参考值与运行输入分开保存。33项中32项属于“维护表报告最优、证明未独立复核”；开发mk10只有报告下界189和BKS 193，不能称最优。当前没有一项被归类为本轮独立核实的最优值。报告分别计算相对报告最优、BKS、下界及同实例同重复A的差距，不能混称“最优差距”；各Hurink变体使用自身参考值。[参考表](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/docs/fjsp-reference-summary.md)仅供离线评价。被评测B/C的显式业务提示词不包含实例名称、参考值、检索入口或其他方案的候选与结果；平台隐式上下文的可见性边界另述。

A在静态问题上采用OR-Tools 9.15.6755的可选区间CP-SAT模型，单线程、每次累计30秒求解预算，重复种子为11/22/33。依据开发集预先固定Brandimarte使用PORTFOLIO_SEARCH、Hurink使用AUTOMATIC_SEARCH，均关闭随机化。B真实调用gpt-6-astra、medium推理，决定完整工序顺序和机台；工具仅依照该顺序计算最早开始时间，不替模型选机、排序、补动作或求解。其表示不支持任意主动闲置。C使用同一模型配置和A的约束模型，选择求解参数与时间分配，查看本条运行的候选、状态、界和检查结果，最多两次求解、累计30秒，并须显式选择最终候选。一次求解后提交应如实称为一次参数选择，不能包装为多轮优化。静态辅助F预先固定三种搜索模式各10秒，取独立可行候选中最小makespan，用于检验固定组合能否解释C的收益。[静态实现审查](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/docs/review-static.md)记录权限和模型等价性检查。

这些静态实例是公开基准，未独立测量模型预训练数据污染。显式业务提示词剔除了实例名称、参考值及检索链接，原生工具事件也单独审计；这不构成模型从未见过相同数据的证明。CLI保存的请求与事件不是服务端最终完整上下文的逐字转储，不能据此宣称完全排除基准记忆。对未见真实工厂数据的泛化仍需另行验证。

Hurink所选变体保持同一基础实例的工艺链和工时，但机器资格集合不嵌套：edata并非rdata的逐工序子集，rdata也并非vdata的子集。平均可选机器数增加因此不能解释为“只在原机器集合上加边”的单因素实验。结果应讨论具体柔性结构变化下的质量、可行率与成本，不能把跨Brandimarte/Hurink的整体差异都归因于设备柔性。

SMT2020是公开仿真测试床，不是企业真实流水。输入保留官方10条工艺路线、4013工步、21投料流和2156批初始WIP，区分913台生产设备与400个虚拟Delay资源；没有使用删去超级热批的软件副本。仿真实现锁定PySCFabSim-revised的RefactoredVersion2025（`ae3d55e…`），并明确采用本轮修订的`smt-adapter-v2`，不是上游或AutoSched的原样复现。官方包与固定源码未查得明确许可证，来源记录不自行补写授权类别。[SMT来源与语义](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/docs/smt-semantics.md)保存归档哈希和全部转换规则。

动态实验每次从官方WIP重新开始，预热0、窗口8小时，仅控制9号非组批设备与790号组批设备，占生产设备2/913≈0.219%。范围外911台生产机及虚拟资源采用三方案相同的固定策略。A以CP-SAT优化当前受控资源的合法lot/batch选择；B直接决定具体lot、机台、组批及等待；C选择同一优化器的权重、种子和时限，再显式应用候选。该优化器只求解当前动作，不实现多步全厂规划。另设预定等待导向固定权重F作辅助。局部合法闭环不能表述为全厂自主排程成功，也不能将范围外固定策略的贡献记作Agent决策。

动态主目标预先固定为两个受控设备族的8小时等待队列面积；同时报告受控完成工序批数、全厂吞吐、完成批周期与延期、终末WIP、批填充、占用及决策成本。窗末未完成批保留，完成者周期均值必须和未完成积压一起解释。占用指标含setup/PM，不等同纯加工利用率。适配器检查组批、换型及连续使用、维护与故障、运输、绑定、抽检、返工和守恒；仍保留明确边界：CQT不启用，初始历史绑定未知，wafer流水采用整lot聚合，lot-cascading只支持已验证时长域并对域外输入拒绝，重叠停机串行累计。这些边界限制向真实工厂及通用设备模型的外推。

模型服务延迟与工厂时间分开处理：控制器在决策点等待真实模型返回，之后在原仿真时刻应用动作；推理、网络和求解的墙钟耗时不会自动注入生产事件时间。只有显式等待动作推进相应仿真时间。因此当前业务指标评价这一同步仿真假设下的动作质量，在线工厂因决策迟到造成的吞吐、等待损失尚未测量。真实服务延迟另列成本，下一轮应验证将它注入事件流后的影响。该说明来自已冻结的`src/smt_control.py`决策循环，并未改变正式实现或指标。

配对场景采用事件键控随机场，避免策略改变随机数调用顺序后错配故障或返工。相同事件键得到同一抽样，但批成员改变会改变加工、运输抽样键；不能声称不同组批仍逐项经历相同加工时长。同一SMT外生种子下的3次重复反映模型或求解执行的变化，不是3个独立工厂场景；模型服务端采样种子不可得。仅3个正式外生场景的结论属于有限场景观察，不据此推断广泛工厂收益。

开发阶段先用手算和故意违规输出验证检查器，再运行真实模型。240工序mk10按输出规模加入开发集，未改变正式/预留选择；显式工序编号输出曾超时，改用紧凑表示后的开发贯通只证明流程可行。独立审查曾发现SMT均匀分布offset被错误减半，以及审计漏接未执行动作、未绑定源字段；修复后运输端点恢复为5至10分钟，正常轨迹通过，原负例被拒，批容量、两槽、返工和件数PM手例补齐。静态求解时限白名单和迟到模型输出接受问题也完成修复，旧失败和旧轨迹均保留。[SMT审查及复测证据](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/docs/review-smt.md)、[静态开发摘要](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/artifacts/development/summary.json)、[动态开发摘要](__LOCAL_PROJECT_ROOT__/experiment_round2_3datasets/artifacts/development/smt_summary.json)不能充作未见正式集结论。

统计以冻结矩阵为分母，逐项列成功、失败、未完成和未开始；失败目标和差距为null，不记0、不删记录。质量均值条件于成功，配对差距注明双方均有效的样本数，并同时展示成功率。B的首次完整排程有效与C的首次动作/求解候选有效分层报告；修订、参数变更和求解调用不混成同一指标。三类数据分别解释，不把makespan和动态业务指标相加形成总冠军。

成本同时报告端到端时间、模型调用、已知input/output及缓存token、累计求解预算与实际耗时；模型开销和模拟器推进、审计开销不隐藏。未知token和实际货币费用均保留未知，不能当作零或估成实际账单；开发协作成本与评测调用分开。正式采用单线程求解、串行运行和统一准入账本，阈值在后续调用前检查，最后一个已准入调用可能产生有界超额。每条记录绑定冻结commit、配置和数据哈希，保留原始模型事件、动作、候选和轨迹；最终结论以独立回放认证为准。流程可复现不意味着新鲜模型输出逐字相同。
