## 题目、范围与复现身份

固定 `prosysscience/FJSP-SMT2020@6253f982df13886ab75d9bc639bfaff045b2829a` 的 PADL-2023、`flex=1`。正式实例 02/05/08 在任何求解结果前按 15/25/30 工序、2+1/2+2/3+3 机台结构预选；开发只用 01/03 与手工 smoke。模型、提示、工具、依赖和代码在正式运行前冻结，校验见 `configs/freeze.json`。原仓库未提供许可证，不将第三方代码冒称自己的开源资产。

这是 SMT2020 衍生的小型静态半导体调度题，保留回流、柔性机台、换型、维护 min/max 计数。该版本没有组批、Q-time、交期目标、故障或动态插单，本轮没有验证这些能力。工时直接用原 pro_time，首机维护标记按原代码视为初始状态而不消耗时间。其他语义边界见 [问题规范](problem-spec.md) 和 [源码审计](source-audit.md)。

A 使用原 ASP 编码及官方原生 clingo-dl v1.5.0 优化控制器，不是 FIFO 或重新建模的 CP-SAT。pip Python 入口缺少论文命令使用的 makespan 优化选项，已通过编译未修改的官方原生入口修复。主目标是 makespan；原 setup 弱约束保留并报告，但控制器不保证在最小 makespan 下继续取得 setup 违例数的二级最优。

## Agent 实际决定了什么

B 的真实模型逐工序输出一个完整动作列表，明确选择派工顺序、组内机台和维护事件。确定性 dispatch 工具只传播这些选择产生的时间下界、计算必需换型并检查累积状态；不选择作业、机台或维护，不含求解器或默认启发式代排。若动作违反约束，返回具体错误，由模型修订整份方案。返回完整且可行的排程后自动验收该候选。

C 用同一模型和推理强度输出结构化 solve/finish 动作。solve 真正调用原求解器，模型选择时间预算、随机种子和求解配置；收到完整排程、独立校验、目标和状态后决定结束或再调用。这里的“工具调用”通过受控 JSON 动作桥接执行，不是声称用了 API 原生 function-call 字段。

## 失败、修复与正确性证据

开发阶段先遇到本地网络沙箱、pip入口缺少原优化功能、旧Codex CLI不能调用指定模型三类环境问题。分别通过受授权网络访问、编译官方原生clingo-dl、改用桌面应用自带的新CLI修复。第一条真实模型探测失败完整保留，不冒充成功调用。语义上发现初始维护、setup=0继承、末维护段min豁免和单工序机台初始setup等边界，均保留锁定源语义。详细过程见 `progress/iterations.jsonl`。

校验器不导入求解器或dispatch。18项关键测试涵盖手算目标、缺失/重复工序、非法机台/时间、加工时长、释放、前置、互斥、维护min/max/初始/类型及换型时间。另有4组源代码对照测试：192个固定候选（6可行、186不可行）、时间边界、单工序机台例外、原经典开发输出的所有witness。主Agent已执行这些测试并复核原始结果。排程记录回放再次逐条重算，不信任 success 字段。

本组正式运行没有最终失败。首次候选不可行及修订次数仍按原记录计入上表，不用最终成功抹除中间问题。

## 首轮观察与下一轮

在本组可行结果上，B 相对配对 A 的平均 makespan 差距为 -4.50%，C 为 -12.77%。若主目标持平，模型调用仍有显著额外延时和用量；持平不等于证明用了更少生产资源。原经典求解器的最优性/限时状态已逐次披露。

这些是两类产品、五道剩余工序、最多30道工序的小样本观察。没有人类排程对照、厂内历史数据或生产上线，因此不能宣称胜过人工、适用于完整Fab或产生真实工厂收益。未做提示消融，也未证明模型选择求解参数优于固定参数；3次调用输出相似不等于独立统计证据。

下一轮优先验证：①扩大未见实例规模并保持全部失败记录，观察B在哪些维护/资源组合先失稳；②用同等求解预算做固定参数与C自适应参数消融，测出模型的实际增量；③单独选择包含批处理的后续版本，重新建立完整批次约束和多目标规范，不能直接给本轮结果加上“组批”标签。自主论文研究、算法进化和模型训练留到后续。
